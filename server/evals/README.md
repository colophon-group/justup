# Model evaluation

Read [the model guide](../../docs/models.md) before changing a task profile or preparing a live check. `intent-heldout.json` and `company-heldout.json` record broader provider-free contracts. `luna-qualification-v1.json` fixes the case order, expectations and repeats; `luna-qualification.mjs` scores only redacted outcomes. Four positive company cases supply only a name, and the repeated company case is one of them. They must return the expected official domain with verified evidence and an observed native web start. For ambiguous companies, a status and named-subject check marks the answer pending; it never certifies whether the text asks the user to distinguish organizations. The pure review finalizer requires an explicit approval or rejection for each exact answer digest, bound to the report digest. A protected reviewer must inspect the transient answer before issuing that receipt. No live review or finalization path is installed. The CLI and queue launcher have a prepared one-use path, but the CLI rejects live execution because no fixed protected qualification service is installed or in the host plan. A later host change must review and install that sandbox before removing the source gate or creating a root grant. Local tests use fake model responses and make no provider or host calls.
