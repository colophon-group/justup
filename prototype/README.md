# Justup interactive prototype

A browser-only mockup of Justup's orange-and-ink design. It uses fictional job listings and 20 fictional companies, with one shared set of observations for the feed, company reports and weekly company-news ribbon (Hiring Wire). No API keys, build step, server or real requests are required. Map-drawing libraries are bundled locally.

## Run locally

From this repository:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory prototype
```

Open http://127.0.0.1:4173.

## Explore the prototype

- Results share an ink frame with a cream masthead and narrow cream surround. The listing surface stays coral so both light and dark company marks retain their established contrast; logos are never recoloured. The frame grows with the feed and keeps the reserved loading/exhaustion area. Mobile spacing retains useful text width.
- Scroll the positions feed. Each additional job starts only when its slot reaches the visible viewport, at least 450 ms after the preceding reveal starts. Background candidate pages are buffered independently. Leaving the tail or backgrounding the tab stops consumption.
- Fresh visits show a compact landing page with “Fresh jobs. No paid placement.”, the working search field with rotating typewriter examples, and four brief feature explanations: no sponsored listings, first-seen freshness, inspectable company coverage, and no recruitment agencies or aggregator/social-media reposts. The coverage link opens the catalogue; the overview heading is “Beat the endless scroll.” The landing title and meta description reflect these policies; this browser-local prototype does not implement production indexing. The feature overview appears only with no saved searches; blank additional tabs keep a compact composer. There are no starting-point buttons. Forty localized, interleaved examples range from short searches to detailed AI-filtering requests, newspaper and editorial work, and gently playful phrasing. Non-software roles feature early and throughout: libraries, teaching, nursing, hospitality, trades, museums, gardening, logistics, fundraising, photography and public transport. References and jokes stay within natural requests. They use natural search language. Typing runs at 24 ms per character, with quicker spaces, a 3.2-second full-prompt pause and extra reading time for longer requests. The full-width input reserves stable space for the detailed prompts. They are decorative, hidden from assistive technology and never become the input value or submit a search. Pointer, keyboard focus, paste and input pause the animation immediately. On blur, it resumes whenever the field contains no meaningful text, including after clearing a previously submitted search; non-empty drafts keep it paused. Saved drafts are preserved. Reduced motion shows one static example; hidden pages, other routes and open dialogs pause the hints. No tabs, result feed or live arrivals start until the first submission; returning visits restore existing searches and drafts.
- Search deletion opens a named confirmation dialog. Keep search or Escape cancels it; deleting an inactive search preserves the current unsent query. The last search can also be deleted; confirmation returns to the mini landing page and remains empty on reload, preserving follows, viewed jobs and company requests.
- A fixed back-to-top button appears after scrolling down. It restores focus to the top navigation and respects reduced motion.
- Companies has All companies, Followed and Requested filters. Requested renders the shared company-row component, with text-size logos, names, company details, request status, single row separators and shared profile links.
- Position search, company search and company discovery share the cream field, typography, inset submit button, border and focus treatment. Company search filters live and supports Enter or Search; discovery uses Find company. Single-line company inputs stay compact.
- The search text is the sole visible description of the request; no generated criteria summary is shown. A single compact options line contains a language icon and selection, plus the “Followed only” checkbox. Both controls use the same type scale, spacing and light interaction treatment; there are no enclosing boxes or followed-company counts. Long language selections shorten visually without limiting the saved selection.
- Edit the complete search text and press Enter. Write your first search, then create additional tabs as needed. This prototype uses a small local interpreter; it does not call a model or implement JEV.
- Click a position row or its arrow to open the full sample posting in a new tab and mark it as viewed. The company name and logo form a separate link to the company’s hiring report in the same tab, with their own hover, pressed and keyboard-focus treatment; they do not trigger posting-row feedback. “Back to search” returns to Positions with the current search and unsent draft preserved. Opening a company report does not mark the position as viewed. Viewed state is shared by all searches within the same account, including New-marker dismissal. Small decorative icons accompany location, workplace type and disclosed pay; labels remain readable, and skills and employment type stay plain. Unknown pay is omitted entirely; skills remain visible without a leading separator. Icons inherit the muted viewed colour.
- Browse and search the company catalogue. It uses the same viewport-gated, 450 ms row reveal as the positions feed. Whole company rows open their profiles; the compact priority action stays independent. Read each row’s coverage status and request priority on an existing setup. Coverage states do not have separate catalogue filters. Both lists share one row component for link hit areas, hover/pressed/focus feedback, arrow targets and responsive edge insets (16 px desktop, 12 px mobile). The company section bar follows its search, matching Positions. The lists have no footers or bottom coverage panels. The company-request action remains in the catalogue header; the end-of-results status uses reserved space.
- Follow companies from catalogue rows or profiles. Follow / Following buttons remain independent of whole-row links, grouped beside the profile arrow on the right. Company and request rows omit website subtitles. The catalogue’s Followed filter combines with the company search text and updates immediately on unfollow. Enable “Followed only” beneath a search to intersect its criteria with your followed set. The scope is saved per tab, query drafts are preserved, and live arrivals respect the limit. With no follows, the empty state links to the catalogue. New company requests automatically follow the company. Users can unfollow without removing the request; explicit unfollows persist across reloads. Manual follows do not create requests.
- Company profiles read as hiring reports: a weekly listing quote, interactive 4W/3M/1Y historical chart, last-14-day snapshot, role and experience mix, reported annual salary ranges by currency, hiring footprint globe, workplace mix and skills. The report uses coral paper, an ink quote panel, cream chart and salary surfaces, and coral chart/range marks. Weekly figures, chart endpoints, role counts, current job rows and Hiring Wire percentages share one fictional observation ledger. These are listing signals, not completed hires or headcount. Salary disclosure includes its sample denominator; missing pay is unknown. Currencies stay separate. Configuring companies have no invented history; delayed monitoring pauses comparisons and leaves chart gaps. Chart range, hover and keyboard inspection, salary currency, Follow and See positions controls work locally. The source record shows last checked and address-based links to every tracked career page. - Company profiles and catalogue/request rows omit headquarters information. Job locations remain visible; the interactive globe highlights hiring countries. Scrolling over the sphere rotates it without zoom or automatic spin. Dragging and arrow keys also rotate; Home resets. The account icon opens the Settings overlay; its temporary account selector previews signed out, Plus, free week, expired and legacy welcome-month accounts. Profiles have separate searches, follows, requests and viewed state. Only paid Plus has priority in this mockup; trial request priority remains a product decision.

- The header shows the large masthead with cream UP., motto and Live edition, without a secondary JUSTUP.WORK link. Large headlines and section/dialog headings use the same bold condensed display face as the wordmark. Body text, inputs, job titles, company names, controls, steps and metadata use the typewriter face. Cream is the shared light interface colour, including the masthead accent, landing promise, dark-button text, live edition, New markers and native choice controls. Company marks retain their original light or dark colours. Row titles, secondary headings, controls and descriptions share a size/weight scale.
- Signed-out and expired accounts preview matches older than 48 hours, still within the last 14 days. The notice shows the exact number of recent hidden matches in this finite mock dataset, scoped to the active search and followed-company limit. No overall position totals appear. Hidden results are absent from preview rows and live arrivals update only the aggregate notice. In production, access and counting must be enforced by the server, with a lower-bound hidden count while JEV evaluation is incomplete.
- When recent matches are hidden, the access prompt overlays at most four inert, decorative row impressions. Rows compress vertically and blur progressively more toward the top (3–13 px), suggesting a deeper stack without a tall wall of blur. The impressions contain no restricted posting titles, company names, links or job IDs and are excluded from assistive technology. Older eligible rows remain sharp below. The count retains its actual search, followed-company and language scope; live updates preserve CTA focus and the preview’s position. Sign-in unlocks real recent fixture rows. Trials use a light access strip, Plus omits the gate, and zero hidden matches produce no decorative stack.

- Simulated sign-in accepts an email, preserves the visitor’s search and resumes pending follows or company requests. No email is sent. New mock accounts receive a free week; the legacy fixture has a 30-day welcome period representing the intended calendar-month offer. Access end dates, illustrative $3 weekly/$10 monthly options, plan changes, renewal cancellation and resumption are interactive. Expiry returns to preview access while keeping saved state. No payments are collected.
- The interface detects the first supported browser language, falling back to English, with English, German, French and Spanish available in Settings. An explicit choice persists across reloads. Dates and interface labels follow the chosen locale; job titles, company descriptions and query text remain original. Reduced motion is also available in Settings.
- Posting languages are a separate, account-specific preference under Settings → Language & display and in the compact options line beneath the search input. Any language is the default, including on browsers whose interface is localized. The picker searches the full 7,928-entry ISO 639-3 catalogue by localized/English/native names and codes, with common languages easy to reach and all other entries available through search and progressive browsing. There is no selection cap. Checkboxes, removable chips, Any language, Done and Cancel support multi-selection without holding modifier keys. Draft choices apply only on Done; Escape and dismissal cancel. Selections persist per account and survive sign-in to a new account. A posting matches any selected language; bilingual fixtures match on either language. The same predicate governs result pages, hidden-match counts and simulated arrivals. Search text and unsent edits are preserved. Posting rows omit language labels; the language scope is communicated only in the search options. Interface language stays independent. Fixture language metadata is explicitly simulated, not inferred production data.

- The cream Hiring Wire beneath the masthead, with ink-black percentage badges, shows six curated fictional WoW listing signals, linking to company profiles, with short headlines, signed percentages and sparklines. It compares mock rolling seven-day snapshots with the preceding seven days; it does not represent live analytics, completed hires or headcount changes. The strip has no title, sample label, visible WoW abbreviation, info panel or control block; it runs as company headlines and percentage changes. The global prototype banner identifies fictional content. It has no pause controls. Pointer hover and clicks keep it moving; keyboard links switch to a static readable strip, and reduced motion freezes it with horizontal scrolling available. The repeat copy is hidden from assistive technology and keyboard order. All new copy is translated into the four supported interface languages.

Searches (including their followed-company scope), followed companies, viewed IDs, requests and confirmed company profiles are saved in localStorage in this browser. Demo controls can reset them. There is no authentication, subscription billing, SSE connection, actual company discovery, real crawler setup or cross-device persistence. The intended application framework remains undecided.

## Company report data feasibility

The prototype does not query Jobseek. Its data is fictional. The current Jobseek schema provides candidate fields for a production report:

- Retained `job_posting.first_seen_at` supports first-observed listing history. Structured occupation, seniority, employment type, location type, locations and technology identifiers support the breakdowns, subject to actual enrichment coverage. Historical listings can contribute aggregates after they leave the 14-day search window.
- Salary min/max, currency and period support disclosed ranges. Production must separate currencies and periods, state sample sizes and handle unknown values. The mockup uses annual base-pay fixtures; it does not establish that every real salary is annual base pay.
- `job_board.last_checked_at`, `last_success_at` and source URLs support the source record. Registration timestamps are not monitoring-start dates. A trustworthy “On record since” date needs a persisted first-success record or coverage history.
- Production comparisons must account for the first bulk import, added/removed career pages, outages and incomplete enrichment. A newly observed backlog must not appear as a sudden hiring boom. Unknown coverage is a gap, not zero hiring.
- The schema does not establish reliable historical filled/closed timestamps, completed hires, headcount or company headquarters. None of these are inferred from listing disappearance or last-seen time.

Schema references: Jobseek `apps/web/src/db/schema.ts` and `apps/crawler/src/migrations/versions/0001_initial_schema.py`. Field availability does not establish production data completeness.
