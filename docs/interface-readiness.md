# Carry the accepted design into the prerelease

The [working mockup](https://justup-working-mockup.sacredchick175064.chatgpt.site/#jobs) is the minimum product design and interaction baseline. Preserve its accepted elements and extend its language where real service states need more. The prerelease is the production application with restricted availability, not a smaller interface. [Product behavior](product-design.md) and the [motion guide](motion-design.md) resolve the accumulated design decisions; the latest accepted version takes precedence over earlier experiments.

Compare the same viewport, route and state against the retained mockup source and visual references. Its public URL is not an immutable release identity. The initial source audit below uses frontend `4fa559b8d453fec61987a06175209551299d00ef` and the retained mockup files `index.html`, `style.css`, `company-report.js`, `company-report.css`, `posting-languages.js`, `search-examples.js`, `surfaces.js` and `wire.js`. The public reference could not be retrieved during this audit. This inventory is not a completed visual comparison or deployed acceptance.

## Extend the design where the product needs it

Use the existing palette, typography, square input/button construction, row insets and dialog patterns for new states. This includes email verification while delivery is unavailable, deliberate free-period activation, billing reconciliation, entitlement expiry, conflicts, recovered drafts, interrupted company setup, SSE reconnects and partial report evidence. Introduce a new visual component when it improves one of those tasks; do not default to unstyled text blocks or unrelated dashboard cards. New copy must explain the user's next action without implementation jargon.

Unavailable data changes the content, not the design requirement. Keep the report's structure and readable missing-evidence treatment; do not fake a trend, salary, source approval, live signal, geography or total to make it look complete. A truthful unavailable state does not satisfy a release dependency that must actually work, such as real live delivery or first-release billing.

The report's reference layout does not authorize its fictional calculations. Snapshot cards and comparisons must name the actual sample, scope and period, not imply total company vacancies or all market hiring. Show only supported history windows. Currency selection changes the displayed source group without converting amounts, annualizing hourly/monthly pay or averaging unrelated bounds; period and sample limitations stay visible. Experience, workplace and skills mixes require structured attributable labels, not inferred personal or employer facts. Keep their designed sections with honest unavailable content until the necessary projection is supported.

## Accept the interface against the actual build

For the exact combined frontend/API/runner candidate, retain desktop and small-screen comparisons for first search, populated search, limited-access results, all three catalogue views, request discovery/confirmation/progress, company report and Settings/access states. Include long titles, mixed logo colors, empty and partial data, keyboard focus, reduced motion and all five locales. Compare typography, linework, spacing, density, color and responsive composition; passing DOM assertions alone does not establish visual fidelity.

Record remaining mismatches on the owning issue with a concrete screenshot or interaction reproducer. Do not mark the prerelease accepted while required design elements or real feature integrations are missing. Product extensions follow the same review and verification path; fictional reference data and development controls stay in isolated tests.
